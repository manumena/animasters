# Hairstyle fit editor

November 25, 2026. The owner approved all six hairstyles in the concept sheet and requested individual assets plus an interface for manual size and position calibration.

Open `preview.html`. Select Curtains, Swept undercut, Rounded curls, High ponytail, Twin tails, or Long layers using the selector or Previous/Next. Drag inside the hair’s outlined rectangle to move it. The horizontal and vertical number fields offer keyboard adjustment in the same 512 px stage coordinates as the production avatar renderer. Size scales width and height together around the center, preserving the asset’s aspect ratio; 100% is the initial fit. The percentage field commits on blur or Enter. Fits are retained independently for each hairstyle.

The editor stores all six fitted rectangles through the host’s widget state. Its standalone wrapper also persists them locally when browser storage is available. Export all six fits displays the complete configuration; Select JSON selects it for copying. `hair-presets.json` contains the initial sizing baselines and depth metadata. `owner-hair-fit-export.json` preserves the owner’s final six-style export, including Swept undercut at x = 133 and Long layers at `[97.82500000000019, 87, 316.35, 314.77219451371576]`; these load as the starting adjustments before newer host state. The pasted HTML spacing and line-continuation escapes were decoded without changing any fitted numbers or outline segments. Dragging does not write either file automatically.

The six original transparent generated PNGs and lossless 512 × 512 WebP review derivatives are in `assets/`. The same folder includes `base.webp` copied from production and `face.webp`, the oval/smile cell extracted from the production face atlas. `generation.json` records each exact prompt, original generated file, and reference images. The built-in image generation tool produced each hair asset separately, using the approved sheet and existing hair sprites as references. Transparent face and neck openings are part of each image.

The owner identified two inner strands in Long layers that belong behind the head, then clarified that the first face-framing locks beneath the curtain bangs should remain in front. That style uses a normalized closed `depth.frontOutline` following the crown, fringe, and face-framing locks down to their curved tips. Straight segments and quadratic bends describe the outline, including its inward turns; it is not a horizontal height cutoff. The complementary region contains the deeper rear strands and renders behind the head and torso. Both regions use the same fitted rectangle, so moving and resizing keep them aligned. The original artwork is preserved. Other styles retain their previous foreground composition. The final export includes the outline alongside the owner’s fitted rectangles, including Long layers at 111% of its original size.

`sprites.js` mirrors the production sprite cleanup and trimming rules. Avatar and face anchors match the app. `source.template.html`, `editor.js`, and `hair-presets.json` are the editable inputs. Run `node build-preview.mjs` to update `source.html` and the inline source, then use the visualize renderer to regenerate `preview.html`. Use `--archive-only` to refresh the saved source without replacing the inline calibration surface.

Browser checks cover all six assets, independent fits, proportional scaling, dragging, switching styles, full JSON selection, reload persistence, and layout at 320 px width.

Implemented on November 25 using the owner’s final export. The app’s `src/avatars/catalog.ts` preserves all six rectangles and the complete Long layers outline. `public/avatars/v1/` contains exact copies of the calibrated WebP inputs. The shared portrait renderer draws rear hair before the head and foreground hair afterward, applies existing hair colors, and retains hat tucking. Both frontend and backend version 1 protocols accept the new hairstyle IDs; older IDs remain valid.
